GitHub Actions for small, fast pull requests

Delivery Guardrails

Two workflows you copy into your team's repos. One stops big or stale pull requests from merging. The other tells Slack when work is stuck before it reaches UAT.

Set it up View the repo
What you get

Two guardrails

pr-rules.yml

PR rules

Blocks merging
  • Fails a pull request that changes more than 500 lines. Lock files, snapshots and generated code don't count.
  • Fails a pull request whose work started more than 8 hours ago, re-checked every hour.
  • The tech lead can allow one with the size-exception or age-exception label.
delivery-alerts.yml

Delivery alerts

Posts to Slack
  • Pull requests open more than 7 hours in your team's repos, drafts excluded.
  • Merged pull requests not on UAT within 7 hours.
  • Runs hourly in office hours. Without a webhook it prints the alerts in the run log, which is useful as a dry run.

Setup · in each repo

Block big or old pull requests

  1. Copy the workflow

    Add .github/workflows/pr-rules.yml (shown below) to the repo's default branch. The hourly re-check only runs from there.

  2. Create the exception labels

    gh label create size-exception --color FBCA04 --description "Allowed over the line limit; tech lead approved"
gh label create age-exception  --color FBCA04 --description "Allowed over the age limit; tech lead approved"

  3. Open any pull request

    The two checks need to report once before GitHub lets you mark them as required.

  4. Make the checks required

    Settings → Rules → Rulesets → New branch ruleset. Target the default branch, turn on Require status checks to pass, add pr-rules/size and pr-rules/age, and set enforcement to Active. Or run this from the repo folder:

    gh api -X POST "repos/{owner}/{repo}/rulesets" --input - <<'JSON'
{
  "name": "PR rules required",
  "target": "branch",
  "enforcement": "active",
  "conditions": { "ref_name": { "include": ["~DEFAULT_BRANCH"], "exclude": [] } },
  "rules": [
    { "type": "required_status_checks", "parameters": {
      "strict_required_status_checks_policy": false,
      "required_status_checks": [ { "context": "pr-rules/size" }, { "context": "pr-rules/age" } ] } }
  ]
}
JSON
Setup · once, in one repo

Alert on stuck work

  1. Copy the workflow

    Add .github/workflows/delivery-alerts.yml to one of your team's repos.

  2. List your team's repos

    gh variable set TEAM_REPOS --body "your-org/orders-api your-org/orders-web your-org/refund-worker"

  3. Add a read-only token

    Create a fine-grained token with access to only those repos and read-only Pull requests, Deployments and Contents. Save it as the secret TEAM_READ_TOKEN. If you watch only the repo the workflow lives in, skip this step.

  4. Connect Slack

    Create an incoming webhook for your team channel and save it as the secret SLACK_WEBHOOK.

  5. Record UAT deployments

    If you deploy with GitHub Actions, give the UAT job environment: uat and GitHub records every deployment. With Jenkins, Argo CD or similar, add this step after a successful UAT deploy:

    id=$(gh api -X POST "repos/$REPO/deployments" --input - --jq .id <<JSON
{"ref": "$DEPLOYED_SHA", "environment": "uat", "auto_merge": false, "required_contexts": []}
JSON
)
gh api -X POST "repos/$REPO/deployments/$id/statuses" -f state=success

  6. Run it once

    Open the Actions tab, choose Delivery alerts and click Run workflow. After that it runs hourly, Monday to Friday, 08:30–18:30 IST.

Settings

Change the limits without editing YAML

Set these under Settings → Secrets and variables → Actions → Variables. Anything you don't set uses the default.

VariableDefaultMeaning
MAX_LINES500Most changed lines in one pull request
MAX_AGE_HOURS8Most hours since the work started
AGE_FROMoldest-commitOr pr-opened, a clock nobody can change

Before you switch on the age rule

Three things to know

Clock hours include nights

Work started at 5pm and opened as a pull request the next morning is already 16 hours old. Consider 24 hours, or start with the age limit as an alert only.

Authors can't fix slow reviews

A pull request waiting on reviewers still turns red at hour 8. Block on size, which the author controls, and alert on age so reviewers act.

Commit dates can be changed

git commit --amend --reset-author resets them. Set AGE_FROM=pr-opened if that matters.

A sensible rollout

  1. Turn on the 500-line block.
  2. Run the age limit as an alert for 2–3 weeks.
  3. Make it blocking once most pull requests already merge in time.
